# ひらがじゃん

ひらがな牌を集めて単語を作る、麻雀風の対戦単語ゲームです。
スマホや PC のブラウザから、友達と同じルームに入って遊べます。

## 遊ぶ

[ひらがじゃんを開く](https://shitake-zense.github.io/hiragajan/)

アプリを開いたら、名前を入れてルームを作るか、友達から教えてもらったルーム ID で参加してください。

## 遊び方

1. 代表者が「ルームを作成する」を押します。
2. 表示された 6 桁のルーム ID を一緒に遊ぶ人へ伝えます。
3. 参加する人は同じリンクを開き、名前とルーム ID を入力します。
4. 人数がそろったら、ホストがゲームを開始します。
5. ひらがな牌を引いたり捨てたりしながら、単語を作って点数を獲得します。

## どんなゲーム？

- 2〜4人で遊べます。
- 1 / 3 / 5 ラウンドから選べます。
- 辞書チェックをON/OFFできます（ON: 辞書に載っている単語のみ確定可能）。
- ひらがな牌を組み合わせて単語を作ります。
- ポン、カン、立直、ロン、ツモがあります。
- ドラ、風、役ボーナスで点数が増えます。
- ラウンドごとの結果と累計順位が表示されます。

麻雀の雰囲気を借りた単語ゲームなので、麻雀を知らなくても雰囲気で遊べます。

## 操作の流れ

自分の番になったら、手牌を見て行動します。

- 牌を引く
- 不要な牌を捨てる
- 作れそうな単語があればあがる
- 条件が合えばポン、カン、立直を使う

画面に出るボタンを押して進めれば大丈夫です。

## うまく入れないとき

- ルーム ID が 6 桁で正しいか確認してください。
- すでにゲームが始まっているルームには入れない場合があります。
- 定員に達しているルームには入れません。
- 画面が止まったように見えるときは、ページを再読み込みしてから入り直してください。
- 別のブラウザやシークレットウィンドウで開くと直ることがあります。

## 注意

このゲームは友達同士で遊ぶための身内向けミニゲームです。

- 辞書チェック（ON時）は約26,000語の常用語辞書を使いますが、すべての単語を網羅してはいません。
- 強い不正対策は入っていません。
- 通信には Firebase / Firestore を使っています。
- 予告なくルールや点数が変わることがあります。

## 開発者向け

このリポジトリはビルド不要の静的サイトです。
GitHub Pages ではルートの `index.html` から `public/index.html` に移動します。

ローカルで確認する場合:

```bash
cd public
python -m http.server 8080
```

主なファイル:

- `public/index.html`: ロビー画面
- `public/game.html`: ゲーム画面
- `public/js/lobby.js`: ルーム作成 / 参加
- `public/js/game.js`: ゲーム進行
- `public/js/utils.js`: 牌、役、点数まわり
- `public/js/dictionary.js`: 辞書チェック用の単語データ（自動生成・約26,000語）
- `public/js/firebase-config.js`: Firebase 設定

### 辞書データの再生成

`public/js/dictionary.js` は [JMdict](https://www.edrdg.org/jmdict/j_jmdict.html)（EDRDG・CC BY-SA 4.0）から
`tools/build-dictionary.mjs` で生成しています。牌セットで物理的に作れる常用語（2〜7文字）のみ収録しています。

```bash
curl -o tools/JMdict_e.gz http://ftp.edrdg.org/pub/Nihongo/JMdict_e.gz
node tools/build-dictionary.mjs
```

### アーキテクチャ

ビルド工程・サーバーコードを持たない、フロントエンド完結型のリアルタイム対戦ゲームです。
状態共有は Firebase Firestore の**単一ドキュメント**（`rooms/{roomId}`）に集約しています。

```
ブラウザA ─┐                    ┌─ onSnapshot（購読）→ 画面再描画
           ├─ Firestore: rooms/{roomId} ─┤
ブラウザB ─┘   （山札・手牌・捨て牌・     └─ runTransaction（排他更新）
                 スコア・役・風・ドラ）
```

- 各クライアントが `onSnapshot` でルームを購読し、変化のたびに `renderGame()` が全 UI を再構築します。
- 状態を変える操作（引く / 捨てる / ポン / カン / 立直 / あがり）はすべて `runTransaction` で行い、同時更新の競合を防ぎます。
- ターン進行は `turnPhase` の状態機械で管理します:
  `draw`（引く）→ `discard`（捨てる・カン・立直・あがり）→ `pon_window`（次手番がポン判断）→ `pon_acquired`（ポン後に単語確定）。

### 設計判断とトレードオフ

- **なぜ Firebase / Firestore か**: 身内 2〜4 人で遊ぶ規模なら無料枠（Spark）で恒久的に収まり、サーバー運用も不要。`onSnapshot` のリアルタイム購読がゲーム同期にそのまま使えるため、最小コードで対戦が成立します。
- **なぜサーバーレス（クライアント権威）か**: 点数計算・あがり判定・シャッフルをすべてクライアントで完結させることで、バックエンド実装ゼロで動くものを最速で形にする方針を採りました。その代償として、後述のとおりチート耐性は限定的です。
- **Cloudflare（Workers / Durable Objects）への移行を検討し見送り**: リアルタイム同期を WebSocket + Durable Objects に置き換える案を比較しましたが、現規模では Firestore で機能・コストとも十分で、移行は学習・実装コストに見合わないと判断しました。将来サーバー権威化する場合の有力な選択肢として残しています。

### テスト

牌・役・点数まわりのピュアな関数（`public/js/utils.js`）を Vitest で検証しています。

```bash
npm install
npm test          # 一括実行
npm run test:watch
```

`utils.js` 末尾の CommonJS エクスポートはテスト用で、ブラウザ実行時は無視されます。

### 既知の課題

現状は「動くものを最短で作る」ことを優先した結果、以下が未対応です（身内向け前提で許容）。

- **クライアント権威設計のため、点数・手牌の改竄を完全には防げない**。Firestore ルールで防げるのは構造的な改竄（フィールド検証・プレイヤー除外・ID 改変の禁止）まで。完全な防止にはサーバー権威化（後述）が必要です。
- **辞書チェックはルーム作成時のオプション**です（デフォルトON）。OFFのルームでは意味のない文字列でも単語として成立します。ONでも辞書（JMdict由来・約26,000語）に載っていない固有名詞や俗語は弾かれます。
- **立直の待ち牌**は、辞書チェックON時は「残り手牌＋待ち牌で辞書の単語が作れるか」を設定時・宣言時に検証します（OFF時は自己申告のまま無検証）。
- **ポン・ロンの権利が下家（次手番）のみ**で、3〜4 人プレイでは麻雀本来の挙動と異なります。
- ルーム ID が 6 桁の数字のため、**総当たりで他人のルームを覗ける**余地があります（ルールでは防げない）。
- Firebase JS SDK が 9.x の compat 版（旧 API）です。

### 今後の展望

- **サーバー権威化**: あがり判定・点数計算・シャッフルを Cloud Functions（または Cloudflare Workers）へ移し、クライアントは入力のみを送る構成にする。
- 辞書 API / 内蔵辞書による単語チェック。
- 待ち牌・ロンのサーバー側検証。
- 全員ポン / 全員ロン対応、プレイヤー切断時のホスト移譲・ターンスキップ。

### 古いルームの自動削除（TTL）

ルーム作成時に `expireAt`（作成から7日後）フィールドを書き込んでいます。
Firestore の TTL ポリシーを一度だけ設定すると、失効したルームが自動削除されます。

```bash
gcloud firestore fields ttls update expireAt \
  --collection-group=rooms \
  --enable-ttl \
  --project=hiragajan-f3887
```

または Firebase コンソール → Firestore →「TTL」から `rooms` コレクションの
`expireAt` フィールドを有効化してください。
